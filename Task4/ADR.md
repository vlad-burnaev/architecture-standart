#### **Архитектурные решения:**

**1. Сервис интеграции депозитов АБС**

Создается новый сервис интеграции депозитов в составе АБС, который:
- Предоставляет REST API для получения ставок системой кол-центра
- Формирует файлы со ставками для партнёрского кол-центра
- Управляет передачей файлов на SFTP-сервер
- Кэширует ставки для быстрого доступа (опционально)

**2. Интеграция системы кол-центра через API**

Система кол-центра получает доступ к ставкам через REST API:
- Прямой запрос к сервису интеграции АБС
- Быстрый отклик (менее 1 секунды)
- Минимальная нагрузка на АБС благодаря кэшированию в сервисе интеграции

**3. Интеграция партнёрского кол-центра через SFTP**

Партнёрский кол-центр получает ставки через файлы на SFTP-сервере:
- Формат файла: CSV или JSON (согласовывается с партнёром)
- Автоматическая загрузка файла при изменении ставок
- Периодическая проверка партнёром наличия новых файлов
- Безопасная передача через SFTP с шифрованием

**4. SFTP-сервер**

Разворачивается SFTP-сервер в инфраструктуре банка:
- Изолированная среда для обмена файлами с партнёром
- Настройка прав доступа для партнёрского кол-центра
- Мониторинг и логирование операций
- Резервное копирование файлов

**5. Технологический стек**

- **Сервис интеграции депозитов АБС**: PL-SQL, REST API (Oracle APEX или отдельный сервис на Java/Node.js)
- **SFTP-сервер**: стандартное решение (например, OpenSSH SFTP или специализированный SFTP-сервер)
- **Формат файлов**: CSV или JSON (согласовывается с партнёром)
- **Интеграция системы кол-центра**: REST API (Java Spring Boot уже поддерживает REST клиенты)

**6. Безопасность**

- Аутентификация и авторизация для API доступа к ставкам
- Шифрование соединений (HTTPS для API, SFTP для файлов)
- Ограничение доступа к SFTP-серверу по IP-адресам партнёра
- Аудит всех операций доступа к ставкам

**7. Синхронизация данных**

- Событийная синхронизация: при изменении ставок в АБС автоматически обновляются файлы на SFTP
- Периодическая синхронизация: партнёрский кол-центр проверяет наличие новых файлов (например, каждый час)
- Версионирование файлов: каждый файл содержит дату и время обновления

### **Альтернативы**
Опишите здесь наиболее важные альтернативные решения.

**Альтернатива 1: Прямой доступ системы кол-центра к БД АБС**

**Описание:** Система кол-центра напрямую обращается к базе данных АБС для получения ставок.

**Почему не выбрано:**
- Нарушает принцип изоляции систем
- Создает дополнительную нагрузку на перегруженную БД АБС
- Требует предоставления доступа к БД внешней системе (риск безопасности)
- Нарушает требование NFR5

**Альтернатива 2: Использование очереди сообщений для передачи ставок партнёру**

**Описание:** Использование очереди сообщений (например, RabbitMQ) для передачи ставок партнёрскому кол-центру.

**Почему не выбрано:**
- Партнёрский кол-центр работает во внешней системе и не может подключиться к инфраструктуре банка
- Требует настройки VPN или других механизмов доступа
- SFTP - стандартный и безопасный способ обмена файлами между организациями

**Альтернатива 3: Использование веб-сервиса (SOAP) для передачи ставок**

**Описание:** Создание веб-сервиса SOAP для передачи ставок партнёрскому кол-центру.

**Почему не выбрано:**
- Партнёр не может делать API-вызовы в инфраструктуру банка
- SFTP проще в настройке и поддержке для файлового обмена
- Меньше требований к инфраструктуре партнёра

**Альтернатива 4: Единый сервис для обоих кол-центров**

**Описание:** Создание единого сервиса, который обслуживает и внутренний, и партнёрский кол-центр.

**Почему не выбрано:**
- Разные требования: внутренний кол-центр нуждается в реальном времени, партнёрский - в файлах
- Разные уровни доступа и безопасности
- Разделение ответственности упрощает поддержку и развитие

**Недостатки, ограничения, риски**

**Недостатки:**
1. **Задержка синхронизации**: Партнёрский кол-центр получает ставки с задержкой (зависит от частоты проверки файлов)
2. **Дополнительная инфраструктура**: Требуется развертывание и поддержка SFTP-сервера
3. **Зависимость от формата файлов**: Изменение формата файлов требует согласования с партнёром

**Ограничения:**
1. **Ограничения партнёра**: Партнёрский кол-центр не может делать API-вызовы, только файловый обмен
2. **Частота обновления**: Партнёрский кол-центр получает обновления не в реальном времени
3. **Формат файлов**: Необходимость согласования формата с партнёром

**Риски:**
1. **Риск устаревших данных**: Партнёрский кол-центр может работать со ставками, которые уже изменились
2. **Риск недоступности SFTP-сервера**: Проблемы с SFTP-сервером могут привести к отсутствию обновлений у партнёра
3. **Риск безопасности**: Передача файлов через SFTP требует тщательной настройки безопасности
4. **Риск нагрузки на АБС**: Дополнительные запросы от системы кол-центра могут увеличить нагрузку

**Меры по снижению рисков:**
- Реализация кэширования ставок в сервисе интеграции для снижения нагрузки на АБС
- Настройка мониторинга SFTP-сервера и автоматических алертов
- Регулярная проверка актуальности файлов на SFTP-сервере
- Настройка резервного копирования и восстановления SFTP-сервера
- Ограничение доступа к SFTP по IP-адресам и использование ключей SSH
- Документирование формата файлов и процесса обмена
- Реализация механизма версионирования файлов для отслеживания изменений
